# 部署手册

> 从零开始部署 Industrial-IoT-Edge-Gateway-System
> 适用系统：Windows 10/11、macOS、Linux（均需终端支持）
> 预计耗时：Docker 方式约 10 分钟（含镜像构建），裸机方式约 20 分钟

---

## 1. 环境要求

| 软件 | 最低版本 | 用途 | 检查命令 |
|------|----------|------|----------|
| Docker Engine | 20.10 | 容器运行时 | `docker --version` |
| Docker Compose | v2.0（docker compose 子命令） | 服务编排 | `docker compose version` |
| Git | 2.20 | 获取代码（可选） | `git --version` |

裸机开发方式额外需要：

| 软件 | 最低版本 | 用途 |
|------|----------|------|
| Go | 1.21 | 编译网关 |
| Python | 3.9 | 模拟器 / 后端 / 告警引擎 |
| Node.js | 18 | 前端构建 |

端口占用要求（Docker 方式）：宿主机 `3000 / 5000 / 502 / 1883 / 8086` 五个端口空闲。Windows 下 502 端口偶被"Modbus 服务"占用，可删除 compose 中 simulator 的端口映射（内网通信不受影响）。

## 2. 方式一：Docker 一键部署（推荐）

### 2.1 获取代码

```bash
cd E:\          # 或任意工作目录
# 方式A：git clone <仓库地址> Industrial-IoT-Edge-Gateway-System
# 方式B：直接解压项目压缩包
cd Industrial-IoT-Edge-Gateway-System
```

### 2.2 一键启动

```bash
cd docker
docker compose up -d --build
```

首次构建需拉取基础镜像并编译（Go 模块下载、npm install），约 5~10 分钟。构建完成后 `docker compose ps` 应看到全部 7 个服务 `Up`（部分带 `healthy`）：

```
NAME                 STATUS
iiot-frontend        Up
iiot-backend         Up
iiot-alert-engine   Up
iiot-gateway         Up
iiot-simulator       Up
iiot-influxdb        Up (healthy)
iiot-mosquitto      Up (healthy)
```

### 2.3 启动顺序说明

Compose 已声明依赖与等待条件，无需人工干预：

1. **influxdb** 先起，健康检查（`SHOW DATABASES`）通过后才继续；
2. 首次启动自动执行 `database/influxdb_init.iql`：建库 `factory_metrics`、创建 30 天保留策略与 5 分钟降采样连续查询；
3. **backend** 在 InfluxDB 健康后启动，初始化 SQLite 规则表并写入两条默认规则；
4. **gateway / simulator / alert-engine / frontend** 并行启动，各自的断线重连机制保证即使上游稍慢也能自动接上。

### 2.4 验证部署

按顺序执行以下五步，全部通过即部署成功：

```bash
# ① 数据库就绪：应返回 factory_metrics
docker exec iiot-influxdb influx -execute "SHOW DATABASES"

# ② 模拟器在写数：日志应每秒打印"寄存器已更新"
docker logs --tail 5 iiot-simulator

# ③ 网关在采集：日志应每秒打印 [采集] + 10 个数值
docker logs --tail 5 iiot-gateway

# ④ API 健康：influxdb 字段应为 "up"
curl http://localhost:5000/api/health

# ⑤ 数据入库计数持续增长（连跑两次对比）
docker exec iiot-influxdb influx -execute \
  "SELECT count(voltage) FROM metrics" -database factory_metrics
```

最后打开浏览器访问 **http://localhost:3000**：

- 顶部状态灯为绿色"实时链路在线"；
- 电压/电流/功率因数/温度四张卡片数值每秒跳动；
- 等待 1~2 分钟后历史趋势图出现曲线；
- 模拟器会以小概率制造电压跌落/电流冲击，告警列表将滚动出现对应记录（也可按 §5.2 主动压低阈值立即触发）。

### 2.5 常用运维命令

```bash
docker compose logs -f gateway        # 实时跟踪某服务日志
docker compose restart gateway        # 重启单个服务
docker compose up -d --build gateway  # 改代码后重建单个服务
docker compose down                   # 停止全部服务（数据卷保留）
docker compose down -v                # 停止并清空全部数据（含历史数据，慎用）
```

## 3. 方式二：裸机分步部署（开发调试）

适合需要频繁改代码、断点调试的场景。建议开 5 个终端窗口，按依赖顺序启动。

### 3.1 安装依赖

```bash
# Python 依赖（模拟器与后端共用一套也可，建议后端单独 venv）
pip install pymodbus==2.5.3                       # 模拟器
pip install flask==3.0.0 flask-cors==4.0.0 \
            flask-socketio==5.3.6 simple-websocket==1.0.0 \
            paho-mqtt==1.6.1 influxdb==5.3.1      # 后端 + 告警引擎

# Go 依赖（网关）
cd gateway && go mod tidy

# 前端依赖
cd frontend && npm install
```

MQTT Broker 与 InfluxDB 可用 Docker 单独起（也可安装本机服务）：

```bash
docker run -d --name iiot-mosquitto -p 1883:1883 \
  -v $PWD/docker/mosquitto.conf:/mosquitto/config/mosquitto.conf:ro \
  eclipse-mosquitto:2.0

docker run -d --name iiot-influxdb -p 8086:8086 \
  -e INFLUX_DB=factory_metrics \
  -v $PWD/database/influxdb_init.iql:/docker-entrypoint-initdb.d/init.iql:ro \
  influxdb:1.8
```

> Windows PowerShell 下 `$PWD` 需改为 `${PWD}`（PowerShell）或绝对路径。

### 3.2 启动模拟 PLC（终端 1）

```bash
cd simulator
python plc_simulator.py
```

成功标志：`模拟 PLC 启动中：Modbus/TCP 服务端 0.0.0.0:502`，随后每秒打印"寄存器已更新"。
（Linux 下绑定 502 特权端口需 sudo，或改源码 `MODBUS_PORT` 为 1502 并同步修改网关配置。）

### 3.3 启动 Go 网关（终端 2）

```bash
cd gateway
go run main.go
```

成功标志：`[Modbus] 已连接设备 127.0.0.1:502`、`[MQTT] 已连接 Broker`，随后每秒打印 `[采集]` 数据行。

### 3.4 启动后端 API（终端 3）

```bash
cd backend
python api_server.py
```

成功标志：`已订阅主题: factory/line1/metrics, factory/line1/alerts`。
验证：`curl http://localhost:5000/api/realtime` 返回带 `values` 的 JSON。

### 3.5 启动告警引擎（终端 4）

```bash
cd backend
python alert_engine.py
```

成功标志：`告警引擎开始运行：检测周期 2s`。

### 3.6 启动前端（终端 5）

```bash
cd frontend
npm start
```

自动打开浏览器 http://localhost:3000（CRA 默认；代理已配置指向 5000）。

## 4. 配置调整指南

| 需求 | 修改位置 | 生效方式 |
|------|----------|----------|
| 采集周期 | `gateway/config.yaml` → `collect_interval_ms` | 重启网关 |
| 更换 PLC 地址 | `gateway/config.yaml` → `modbus.host/port` | 重启网关 |
| 增删测点 | `gateway/config.yaml` 寄存器表 + 模拟器 `encode_registers` 对齐修改 | 重启两者 |
| MQTT 主题 | 网关 `mqtt.topic` 与后端环境变量 `TOPIC_METRICS` 同步改 | 重启网关/后端 |
| 告警阈值 | 调 `PUT /api/rules/{id}`（推荐，免重启） | 2 秒内自动生效 |
| 数据保留期 | `database/influxdb_init.iql` 的 RP | 重建数据库 |
| 容器内网关配置 | `gateway/config.docker.yaml`（服务名寻址） | 重建镜像 |

## 5. 验证告警链路（功能验收）

### 5.1 触发告警

将电压上限压到正常波动区之下（正常约 217~223V）：

```bash
curl -X PUT http://localhost:5000/api/rules/1 \
  -H "Content-Type: application/json" -d '{"max_value": 210.0}'
```

预期：2~4 秒内仪表盘"告警列表"滚动出现红色/橙色条目"voltage 超上限: 当前值 21x.xx > 210"，且因去抖状态机持续越限期间只出现一次。

### 5.2 恢复与再触发

```bash
curl -X PUT http://localhost:5000/api/rules/1 \
  -H "Content-Type: application/json" -d '{"max_value": 240.0}'
```

告警引擎日志出现"已恢复正常区间，告警解除"。再次压低阈值可触发第二次告警——完整验证状态机周期。

## 6. 常见问题排查（FAQ）

**Q1：`docker compose up` 后 gateway 日志一直"连接 Modbus 设备失败"？**
模拟器容器未就绪或 502 端口冲突。`docker logs iiot-simulator` 查看报错；Windows 宿主机 502 被占用时删除 compose 中 simulator 的 `ports: "502:502"` 映射（内网通信不受影响）。

**Q2：前端卡片一直显示 "--"，状态灯红色？**
按链路逐跳排查：`docker logs iiot-gateway`（是否在采集）→ `mosquitto_sub -h localhost -t 'factory/line1/metrics' -v`（总线是否有数据）→ `curl localhost:5000/api/health`（后端是否 up）。浏览器控制台（F12）查看 WebSocket 是否连到正确端口。

**Q3：趋势图空白？**
InfluxDB 尚无历史数据，等待 1~2 分钟；或降采样连续查询未建（检查 `influx -execute 'SHOW CONTINUOUS QUERIES'`）。

**Q4：`influxdb` 容器反复重启？**
数据卷损坏或磁盘满。`docker compose down -v` 清卷重来（会丢历史数据）。

**Q5：Windows 下 python 报 `ModuleNotFoundError: pymodbus`？**
确认安装的是 2.x 版本：`pip install pymodbus==2.5.3`；3.x 的 API 不兼容本程序。

**Q6：502 端口在 Linux 上绑定报 Permission denied？**
特权端口需 root：`sudo python plc_simulator.py`，或用 1502 端口方案（见 §3.2）。

## 7. 卸载

```bash
cd docker
docker compose down -v      # 停止容器并删除数据卷
docker rmi iiot/gateway:1.0 iiot/backend:1.0 \
             iiot/frontend:1.0 iiot/simulator:1.0   # 删除自建镜像
# 项目目录可直接删除，本机环境无其他残留
```
