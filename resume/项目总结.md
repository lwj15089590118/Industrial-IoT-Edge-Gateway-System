# 项目总结

在这个《工业物联网边缘网关系统》项目中，我担任系统架构设计与核心开发的角色，独立完成了从需求分析、架构设计、编码实现到容器化部署的完整闭环。项目模拟了工厂配电柜数据的采集、传输、存储、监控与告警全过程，覆盖了"设备—边缘—平台—应用"四级架构，是一次对工业物联网全栈技术体系的完整实践。

**在系统架构设计方面**，我主导了整体技术选型与模块划分。针对工厂数据"多源异构、时序为主、实时性要求高"的特点，我设计了以 MQTT 消息总线为核心的数据管道：模拟 PLC 通过 Modbus/TCP 暴露测点，Go 网关负责协议转换，Flask 后端订阅落库 InfluxDB，React 前端经 WebSocket 实时渲染。我在架构评审中坚持"单一职责 + 消息解耦"的原则，刻意把告警引擎做成独立进程而非后端的后台线程，实现了故障隔离——引擎崩溃不影响 API 服务，规则调整也无需重启后端。事实证明这一决策在后续联调中大幅降低了排障复杂度。

**在 Go 网关开发方面**，我基于 goburrow/modbus 与 paho.mqtt.golang 实现了边缘采集核心。网关支持从 YAML 配置文件加载寄存器点表，对 10 个保持寄存器按 0.1V、0.01A 等系数完成量纲换算，以每秒一次的频率经 QoS1 发布到 MQTT。我重点打磨了可靠性：针对 Modbus 与 MQTT 两条链路分别实现了惰性重连与指数退避重连策略，配合 context 信号处理实现容器化场景下的优雅退出。这段开发让我对工业协议的字节级细节（大端序、16 位无符号限幅）和并发连接的状态管理有了实战级理解。

**在前后端联调方面**，我打通了从数据到可视化的"最后一公里"。后端提供实时、历史、告警规则三类 REST 接口，并通过 Socket.IO 将每秒一帧的测点数据实时推送给前端仪表盘。联调中最棘手的问题是量纲换算不一致导致的曲线整体偏移，我通过"模拟器与网关两端日志逐秒对账"定位到点表系数未对齐，由此沉淀出"点表契约先行"的团队规范；此外还解决了大时间跨度下趋势图卡顿的问题——按查询范围自适应聚合窗口，将两万多个数据点降采样到百余个。

项目最终通过 Docker Compose 实现七个服务一键部署，断线重连、告警去抖等边界场景均通过验证。这个项目也让我完整体验了从设计文档、接口契约到交付手册的工程协作流程，明白了文档不是负担而是团队规模的放大器。

回顾全程，我最大的收获不只是技术栈本身，而是建立了"契约先行、故障隔离、可观测性内建"的工程思维。下一步我计划为网关增加断点续传缓冲，并在告警引擎中引入趋势预测，让这套系统从"能跑"走向"好用"。
